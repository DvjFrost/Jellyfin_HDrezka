# Предварительный план: загрузки HDrezka в локальную медиатеку

Статус: обсуждение. Код функции не реализован; в GitHub ничего не отправлять до отдельной просьбы пользователя.

## Цель

Загрузка выбранного фильма, отдельных серий, сезона или сериала на сервер Jellyfin с выбором бесплатной озвучки и качества; готовые файлы размещаются в пользовательской локальной медиатеке фильмов или сериалов. Клиент телефона или телевизора не является местом хранения.

## Что уже есть

- `HdrezkaSource`: запрос списка озвучек, сезонов и доступных ссылок для конкретного фильма или серии. Платные озвучки отфильтрованы.
- `StreamParser`: извлечение качества и URL, исключение Ultra. Сейчас из альтернатив `or` сохраняется только последний URL; тип прямого файла не определяется.
- `MediaSelection`: ограничение обычным 1080p, выбор наиболее высокого доступного качества не выше заданного.
- `MirrorClient` и `MirrorSessionRegistry`: общая сессия зеркала, Anubis и прекращение запроса зеркала при HTTP 500.
- `CdnSelection`: выбор хоста CDN; для воспроизведения передаются Referer и User-Agent.
- Медиатеки `Фильмы HDrezka` и `Сериалы HDrezka` создаются плагином и содержат служебные `.strm`-записи. Загруженные файлы в эти каталоги без отдельного проектирования не складывать.

## Вывод по RemoteUpload

`GrandguyJS/media-upload-plugin` умеет сохранять URL на сервер, но текущий обработчик `upload_url` принимает только ссылку, использует обычный HTTP GET и записывает ответ в конечный файл. Выбора озвучки и качества HDrezka, передачи произвольных заголовков, определения HLS и безопасного возобновления в этом обработчике не видно. Проект ссылается на Jellyfin 10.9.9 / .NET 8; совместимость с нашим Jellyfin 12.4 не проверена. Его подход к странице задач можно изучить, но базовый загрузчик целесообразно реализовать внутри нашего плагина.

## Предварительные решения

1. Первый этап — прямые файлы MP4. Наличие прямой ссылки в реальных ответах пока не подтверждено в этой проверке: требуется исследовать ответ и заголовки на ограниченном числе выбранных видео. Тестовые фикстуры проекта не являются доказательством поведения сайта.
2. HLS / другие варианты не считать MP4 по расширению URL. Если прямого файла нет, показать причину; FFmpeg как отдельный следующий этап или опция после обсуждения.
3. Ограничение — обычное 1080p включительно, Ultra исключено. Вопрос: при недоступности выбранного качества автоматически брать ниже или требовать точное совпадение? Возможны оба режима с прозрачным отображением фактического качества.
4. Администратор выбирает назначение отдельно для фильмов и сериалов: существующую локальную медиатеку соответствующего типа либо создание новой. При создании указываются название и папка на сервере; если у существующей медиатеки несколько папок, выбирается конкретная. Проверяются доступность и права записи. Существующие файлы автоматически не перезаписывать; политику совпадений согласовать.
5. Запускать из отдельной страницы загрузок на сервере; веб-браузер и мобильный Jellyfin Web — первые целевые клиенты. Меню карточки и Android TV требуют отдельной проверки возможностей их интерфейсов.
6. Загрузки разрешать только пользователям с разрешением, выбранным администратором; к интерфейсу и API применять серверные проверки, не полагаться только на скрытые кнопки.
7. Начальная параллельность — одна загрузка; настройки ограничения скорости и количества одновременных задач можно добавить позже при реальной необходимости.

## Этапы реализации

### 1. Контролируемое исследование протокола

- Проверить исходный ответ сервера для выбранного фильма и нескольких серий, включая альтернативы `or`, на том же зеркале и с существующей сессией. Не печатать URL с токенами и cookie в публичные логи.
- Определить прямой MP4 по ответу и содержимому, статусу, Content-Type и пробным байтам, а не только по суффиксу. Проверить влияние `Referer`, `User-Agent`, CDN и срока жизни ссылки.
- На небольшом диапазоне проверить поведение Range / 206 и доступность длины; не скачивать всё множество вариантов. Подтверждать соответствие байтового диапазона и ресурса, а не просто наличие заголовка.
- Если зеркало вернуло HTTP 500, прекратить обращения и остановить работу в соответствии с просьбой пользователя; сообщить, не запускать автоматический повтор. Ошибки CDN учитывать отдельно, с явным отображением причины.

### 2. Формирование вариантов

- Вынести представление альтернативных ссылок, сохраняя порядок и типы для каждой озвучки и качества. Адаптировать существующее воспроизведение без изменения выбранного им варианта по умолчанию.
- При формировании очереди хранить идентификатор видео, озвучки, номера сезона / серии и выбранное качество, а не постоянную ссылку с временным токеном.
- Получать свежую ссылку перед каждой загрузкой, использовать общую сессию и выбранный CDN. На сериалы — отдельная задача на каждую серию.
- Учесть отсутствие озвучки / качества в отдельных сериях и не выдавать платные озвучки.

### 3. Очередь и сохранение файла

- Персистентные состояния: ожидает, получает ссылку, загружается, проверяется, готово, ошибка, отменено; прогресс по байтам и скорости, без токенов в журнале.
- Передача потокового ответа в отдельный временный `.part`; один активный файл, проверка свободного места, ограничение разрешённых путей и защита от обхода директорий и произвольных ссылок.
- Прерывание и повтор: использовать Range только после проверки поддержки и идентичности содержимого. Если тот же ресурс после смены CDN / ссылки не доказан, не склеивать разные байты; начать безопасно заново или сообщить об ошибке.
- При завершении проверить статус, длину при её наличии, валидность контейнера и отсутствие обрыва; `.part` не считать готовым файлом. Проверка контейнера не всегда доказывает полную целостность видео — учитывать доступные источником признаки.
- Использовать атомарную публикацию готового файла на целевом томе; не перезаписывать существующие файлы без выбранной пользователем политики. Восстановление очереди после перезапуска проверить отдельно.

### 4. Выбор назначения и импорт в медиатеку

- Показать существующие медиатеки подходящего типа, позволить выбрать папку из её путей или создать новую медиатеку на сервере. Не выбирать служебные каталоги потоковых записей HDrezka как место загрузки по умолчанию.
- Для новой медиатеки задать имя и путь, проверить доступ сервера к записи и создать папку / медиатеку только после явного сохранения настроек. Повторное сохранение не создаёт дубликаты.

- Фильм: `Название фильма (год).mp4`, например `Одиссея (2026).mp4`; если год неизвестен, не выдумывать его. При необходимости можно поместить файл в одноимённую папку для корректной работы локальной медиатеки.
- Сериал: `Название сериала (озвучка)/Сезон 01/S01E01 Название серии.mp4`, например `Доктор Хаус (Дубляж)/Сезон 01/S01E01 Название серии.mp4`. Если названия нет — `S01E01 Серия 1.mp4`; не дублировать префикс `S01E01` в названии.
- Jellyfin 12.4 содержит поддержку ключевого слова `сезон` в определении номера сезона; всё равно проверить на реальной локальной библиотеке, включая несколько озвучек одного сериала и одинаковые названия.
- Очищать запрещённые символы имён Windows, учитывать длину пути и совпадения. Не помещать недокачанные файлы в сканируемые папки.
- Папка сериала по решению пользователя включает название озвучки. Проверить, как Jellyfin сопоставляет такие папки: разные озвучки могут появиться отдельными сериалами; не обещать объединение без проверки. Для нескольких качеств дополнительно проверить варианты Jellyfin и не создавать случайных дублей.
- Сохранить доступные описания / постер при отсутствии TMDB, не нарушая пользовательские правки. После готовности обновлять только затронутую библиотеку / каталог.
- Проверить открытие локальной копии и при недоступном зеркале. Учитывать отдельно историю просмотра: синхронизация прогресса разных карточек не гарантирована.

### 5. Названия серий в карточках HDrezka

- Изучить график выхода серий на уже загруженной странице сериала: проверить, встроен ли он в HTML или запрашивается отдельно, как размечены сезоны, серии и русские / оригинальные названия, и нужны ли дополнительные запросы. Сначала использовать имеющиеся материалы; при проверке зеркала соблюдать остановку при HTTP 500. Пока структура графика не подтверждена.
- Сопоставлять названия строго по ID сериала и номерам сезона и серии, а не по порядку строк; использовать только для эпизодов, существующих в списке доступных бесплатных озвучек. Запланированные, но ещё не вышедшие серии не превращать в доступное видео.
- Для каждого эпизода брать русское название, если оно указано; иначе исходное доступное название; если обоих нет — сохранять `Серия N`. Не подставлять даты, язык или служебные подписи как название.
- Одну и ту же запись названия использовать в обычной карточке сериала и при именовании локального файла, независимо от загрузки. Номер сезона и серии оставлять отдельными метаданными Jellyfin, чтобы клиент мог вывести `S02E14 Название` без двойного префикса.
- При повторном открытии карточки обновлять уже созданные эпизоды, в том числе их альтернативные версии озвучки, не меняя ID, историю просмотра или ручные / заблокированные метаданные. По возможности обновлять названия из уже загруженной карточки без отдельных запросов на каждую серию.
- Проверить реальные примеры «Доктор Хаус» и «Сверхъестественное»: наличие русского / оригинального названия, его отсутствие, разные форматы нумерации, график без данных, исходный HTML с проверкой / ошибкой и повторное обновление после перезапуска. Учитывать, что конкретное отображение префикса контролирует клиент Jellyfin, и проверить телефон и отдельно Android TV.
### 6. Интерфейс и проверка

- На странице выбора: поиск по локальному каталогу, карточка, бесплатная озвучка, качество, фильм или серии / сезон / все серии, папка назначения. Для каждой серии показывать недоступность отдельно.
- Страница очереди: ход, результат, причина ошибки, повтор, отмена; управление после перезапуска и очистка временных файлов только в каталоге плагина.
- Локальные тесты без сайта: альтернативы, валидный MP4 / HTML / плейлист, Range и обрыв, смена токена, неверная идентичность, 500 зеркала, отмена, исчерпание места, недоступная папка, конфликт имени, сохранение очереди.
- На тестовом сервере: один небольшой фильм и ограниченное число серий, проверка размера и просмотра локальной копии, перезапуск, тест без зеркала; сравнить фактическую озвучку и качество и проверить пользователей с разными правами. На телефоне проверить доступный интерфейс; Android TV проверять на конкретном клиенте.
